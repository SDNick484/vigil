# vigil hub Implementation Plan

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:subagent-driven-development (recommended) or superpowers:executing-plans to implement this plan task-by-task. Steps use checkbox (`- [ ]`) syntax for tracking.

**Goal:** A vigil in hub mode that lists every machine's pushed sessions through the existing API, scoped credentials (`read`, `push`, `full`), Cloudflare Access verification for proxied requests, a push client on each machine, and an Alpine install for the always-on host.

**Architecture:** The guard in `vigil.web.security` gains a `Grant` (scope plus bound machine) for every admitted request and one `authorize` rule table; Access assertions are verified in `vigil.web.access` before the guard decides. Hub mode (`mode = "hub"`) replaces the index with `vigil.hub.HubStore` (one JSON snapshot per machine, written atomically), fed by `/ingest/{name}/*` and read by the existing `/api/v1` handlers through the in-memory filtering peers already use. Machines run `vigil.push.HubPusher` inside `vigil serve`, driven by the watcher's scan callback and a slow `LiveStatus` probe timer.

**Tech Stack:** as today (Python 3.14, FastAPI, Jinja2, htmx, SQLite, httpx, pytest, ruff, mypy --strict); adds `pyjwt` and `cryptography` (runtime) in Task 5.

**Spec:** `docs/superpowers/specs/2026-11-25-vigil-hub-design.md`

## Global Constraints

- Everything in `CLAUDE.md` "Global Constraints" holds, as amended by spec §11 (Tasks 2, 9, 12 edit those lines).
- Verification gate, before every commit: `ruff check . && ruff format --check . && mypy && pytest`.
- `/api/v1` is read-only and fields are only ever added there; write endpoints (`/ingest/*`) live outside it.
- `requires-python = ">=3.14"` stays; Alpine gets a standalone CPython 3.14 build, never a lower `requires-python`.
- Repository is public: placeholders only (`laptop`, `desk`, `hub.example.com`, `example-team.cloudflareaccess.com`, `author@example.com`, `/home/user/...`, TEST-NET addresses `192.0.2.x`). Tokens in tests are obvious placeholders.
- Tests never launch real `claude`: `fake_bin` puts recording fakes on PATH; hub-mode tests install a fake `claude` and assert it was never called.
- Every PR adds one `CHANGELOG.md` line under `[Unreleased]`; one PR per issue, `Closes #N`, conventional commits.
- Append points: routers appended to `ROUTERS` in `src/vigil/web/app.py`; fixtures appended to `tests/conftest.py`; migration as a new numbered file.
- Scopes: `read` = `GET`/`HEAD` on `/api/v1/*` only; `push` = `PUT /ingest/{name}/sessions` and `POST /ingest/{name}/heartbeat` for its bound name only; `full` = everything vigil's pages can do, not ingest. Insufficient scope → 403 naming the needed scope. Local (loopback) requests are `full` with no token.
- `server.token_file` keeps meaning a `full` token; `[[server.tokens]]` entries: `file`, `scope`, `machine` (required for `push`, forbidden otherwise); two entries with the same token → startup error.
- Access: assertion from `Cf-Access-Jwt-Assertion` only; RS256; `aud` contains a configured value; `iss == https://<team_domain>`; `exp`/`nbf`/`iat` with 30 s leeway; certs at `https://<team_domain>/cdn-cgi/access/certs`, cached 1 hour, re-fetched at most once a minute for an unknown `kid`; no keys → every assertion fails. Identity: `email` claim (users, case-insensitive) or `common_name` (service tokens).
- Once `[server.access]` is set, a proxied request must carry a valid assertion; a bearer token is not accepted in its place.
- Snapshot: `format` 1; ≤ 500 sessions, one per chain, unarchived, active in the last 30 days, newest first; body ≤ 8 MiB (413); malformed → 422 naming the first problem; text cut to 500 characters; digest = SHA-256 hex of canonical JSON (sorted keys, separators `(",", ":")`) of the `sessions` array as received.
- Push: `hub.live_interval` 60–3600, default 900; push at most once every 5 s; heartbeat every 60 s; back-off 5 s doubling to 5 min; 3 s connect / 10 s total timeout; no redirects, `trust_env=False`; credentials only to `hub.url`.
- Hub: `hub_mode.stale_after` 30–3600, default 180; storage `$XDG_DATA_HOME/vigil/hub/<name>.json` (0600, dir 0700); `last_seen_at` flushed at most once a minute.
- Login cookie `SameSite=Lax`; every state-changing request still needs the same-origin `Origin`.

## Review Focus

1. **A tunnel on loopback once Access is set.** cloudflared connects from `127.0.0.1` with `Cf-Connecting-Ip`/`X-Forwarded-For`, or a local client names the public host without proxy headers: both are not local and not "direct" (spec §8.3), so they need a valid assertion; a valid `full` bearer alone gets 403, and with a valid assertion an `Authorization` header is ignored. Owned by Task 7 (`test_tunnel_on_loopback_needs_assertion`).
2. **Clock skew on the JWT.** `iat`/`nbf` 20 s ahead and `exp` 20 s past are accepted; 45 s ahead or past are refused with 403 naming the claim. Owned by Task 6 (`test_clock_skew_within_leeway`, `test_clock_skew_beyond_leeway`).
3. **A machine pushing while the hub restarts.** Connection refused → back-off, serving unaffected; the hub comes back with no or an older file → heartbeat gets 409 and the full `PUT` goes in the same step; a half-written temporary file left by a crash is ignored at load and the previous snapshot is served. Owned by Task 11 (`test_leftover_temp_file_ignored`) and Task 18 (`test_hub_restart_recovers`).
4. **A huge or deeply nested snapshot.** A chunked body without `Content-Length` is cut off at 8 MiB + 1 byte read and answered 413; `[` nested 100 000 deep is 422, never 500; 501 sessions is 422. Owned by Task 12 (`test_ingest_oversized_chunked`, `test_ingest_deeply_nested_is_422`, `test_ingest_too_many_sessions`).
5. **The Access certs endpoint slow or down.** The fetch runs off the event loop under one lock: concurrent assertions trigger one fetch, loopback requests are served meanwhile, and a failed fetch answers 403 (fail closed) and is retried no sooner than a minute later. Owned by Task 6 (`test_concurrent_verifications_fetch_once`, `test_unreachable_certs_fail_closed`) and Task 7 (`test_slow_certs_do_not_block_local_requests`).

## Deviations from the spec

- Spec §6.3 says `GET /api/v1/sessions/{id}` has `resume_command` "`claude --resume <id>`". The existing `vigil.commands.resume_command` gives `cd <cwd> && claude --resume <id>`; the hub reuses it unchanged (Task 13), which also serves §6.4's copy command.
- Spec §7 says listing reuses the peers' in-memory code. `vigil.peers.filter_sessions` takes no `since`; Task 13 adds `since` and makes it generic over `SessionRow` rather than writing a second filter.
- Spec §6.2 puts the push identity in `{name}` but `machine` in today's config allows any printable text and defaults to the host name. A machine with `[hub]` must set `machine` to a name of the `peers[].name` form (Task 16); that is a new config error.
- `PeerSession.stale` moves to `SessionRow.stale` (Task 13) so the new `stale` field serializes from one place; `PeerSession` behaviour is unchanged.
- Spec is silent on `/api/v1/usage`, `/api/v1/catalog` and the `/usage` page in hub mode. Both may run `claude` (`refresh_sources`), which §11 forbids on a hub, so they answer 404 there (Task 9). `/api/v1/projects` is computed from the stored sessions (Task 13); `/api/v1/peers` is `[]` (peers are refused with hub mode).

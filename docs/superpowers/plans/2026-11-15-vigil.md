# vigil Implementation Plan

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:subagent-driven-development (recommended) or superpowers:executing-plans to implement this plan task-by-task. Steps use checkbox (`- [ ]`) syntax for tracking. Each task is filed as one `Prompt:` issue and lands as one PR.

**Goal:** A local service, web UI and CLI that index every Claude Code session on a Linux machine, resume one with one click in the right folder, and show Claude Code usage against what the installed version offers; then (v2) remote access and multiple machines.

**Architecture:** One Python package. An incremental indexer reads `~/.claude/projects/**/*.jsonl` into SQLite; a FastAPI app serves server-rendered pages (Jinja2 + htmx) and a read-only JSON API on loopback; a resume launcher drives `claude --bg` / `claude attach` (tmux fallback) and a terminal. The CLI reads the same index.

**Tech Stack:** Python 3.14, FastAPI, uvicorn, Jinja2, htmx (vendored static file), SQLite (stdlib `sqlite3`), `watchfiles`, `tomllib`, argparse; pytest, ruff, mypy --strict; GitHub Actions.

**Spec:** `docs/superpowers/specs/2026-11-15-vigil-design.md`

## Global Constraints

- `requires-python = ">=3.14"`; CI runs on Python 3.14 only.
- Distribution name `vigil-sessions`; import package `vigil`; console script `vigil`. src layout (`src/vigil/`).
- License MIT.
- Linux only. WSL2 counts as Linux.
- vigil never writes, renames or deletes anything under the Claude home (`~/.claude` or the configured `claude_home`). Tests assert this with a read-only fixture tree.
- No code or concepts specific to any private tool; other tools integrate through the public API.
- v1 binds to `127.0.0.1` only; any other bind address is a startup error.
- Resume may only run `claude` (or `tmux` in fallback) against a session ID present in the index. The only extra flags are those in `resume.default_flags`, allow-listed to `--remote-control`, `--model`, `--effort`, `--permission-mode`, `--name`.
- Indexed transcript text is truncated to 500 characters per field; full transcripts are read from disk on demand and never copied elsewhere.
- Shell history: opt-in (`usage.shell_history`, default `false`); keep only `claude` invocations; store subcommand and flag names and a timestamp only, never values or prompts.
- No hardcoded list of Claude Code features; the catalog comes from the installed binary's `--help`.
- Default port `7787`, configurable.
- Config at `$XDG_CONFIG_HOME/vigil/config.toml`; data at `$XDG_DATA_HOME/vigil/index.db`.
- Verification gate (CI runs exactly this): `ruff check . && ruff format --check . && mypy && pytest`.
- Tests never launch a real Claude session or a real terminal; they put fake `claude`, `tmux`, terminal and `wt.exe` executables on `PATH` that record their argv and cwd.
- Every PR updates `CHANGELOG.md` under `[Unreleased]` (one line per change).

## Review Focus

1. **A transcript whose last line is half-written** (Claude Code is mid-write): the line is skipped and the stored offset stays at the start of that line, so the next scan reads it whole. Owned by Task 3.
2. **A session whose working directory was deleted or moved**: it still lists and shows; Resume refuses with "folder no longer exists: <path>" and starts nothing. Owned by Task 5.
3. **`claude` missing from `PATH`, or a version without `agents`/`--bg`**: indexing, listing and the UI still work; status shows `unknown`; resume falls back to tmux, or, with no tmux, refuses with a message naming what is missing. Owned by Tasks 4 and 5.
4. **Non-UTF-8 bytes in a transcript or a history file**: decoded with replacement, no crash, the rest of the file still parsed. Owned by Tasks 2 and 9.
5. **A very large transcript that grows** (tens of MB): a rescan reads only the appended bytes. Owned by Task 3.
